# 《AI Agent 框架工程实践》教材总纲

## 1. 本教材处于什么阶段

第一阶段解决的是：

> **Agent 的基础机制是什么？**

你通过手写代码理解了 Tool Calling、Agent Loop、State、Memory、Planning、Context、Checkpoint、HITL、Tracing、Harness 等。

第二阶段解决的是：

> **成熟框架如何重新组织这些机制？面对真实项目时应该如何选型？**

因此本教材不会再从“怎么调用大模型 API”开始。

## 2. 学习目标

完成本教材后，应能够回答：

1. Agent Framework、Orchestration Runtime、Agent SDK、Harness 分别是什么？
2. Spring AI 与 LangChain4j 为什么看起来相似，但设计风格不同？
3. 为什么已经有 Spring AI，还可能需要 LangGraph？
4. Google ADK 的 Agent-first 思路解决了什么问题？
5. OpenAI Agents SDK / Claude Agent SDK 或 Tool Runner 与普通应用框架有什么不同？
6. 一个框架“替你写掉 Agent Loop”意味着什么？
7. 框架是否真的消除了 Context / State / Memory / Tool Design 的复杂性？
8. 如何给 Java/Spring 业务系统选 Agent 技术栈？
9. 什么情况下应该放弃单纯 Framework，转而使用 durable orchestration / harness？
10. 如何避免因为框架抽象而丧失可观察性和控制力？

## 3. 教学方法

每章固定包含：

- 为什么要学习它；
- 通俗解释；
- 与第一阶段手写组件的映射；
- 关键抽象；
- 最小 Demo；
- Codex / AI 编程工具实现 Prompt；
- 观察点；
- 常见误区；
- 思考题与答案；
- Framework Mapping。

## 4. 三个 Benchmark

### Benchmark A：Stateful Agent

用于比较：

```text
Plain Java Baseline
       vs
Spring AI
       vs
LangChain4j
```

能力：

- Conversation
- Tool Calling
- Agent State
- 简单 Plan
- Long-term Memory
- SQLite
- 简单 Web Debugger

### Benchmark B：Long-running Agent

用于 LangGraph：

- State
- Node / Edge
- Checkpoint
- Interrupt
- Resume
- HITL
- Retry / Replan

### Benchmark C：Multi-Agent

用于 Google ADK / Agent SDK：

- Coordinator
- Specialist Agents
- Sequential / Parallel / Loop
- Delegation / Handoff
- Session / Trace

## 5. 为什么不让所有框架做完全相同的 Demo

横向比较需要相同业务，但框架也有自己的强项。

因此：

- Spring AI / LangChain4j 用完全相近的 Stateful Agent；
- LangGraph 用 Long-running Agent 展示 durable orchestration；
- Google ADK / Agent SDK 用 Multi-Agent 展示 Agent composition。

这样既能比较，也不会为了“公平”把框架用在不擅长的地方。

## 6. 边界

本教材不重点覆盖：

- 模型训练；
- GPU 推理；
- Prompt Engineering 入门；
- Vector Database 产品大全；
- 云原生部署大全；
- 大型前端开发；
- 每个框架所有 API。

我们只学习足以形成**框架认知和技术选型能力**的关键路径。
