## 2. 为什么不做一个 Maven 父工程管理所有东西

第一阶段所有 Demo 都是 Java，所以 Maven 多模块很自然。

第二阶段不同框架可能使用：

- Maven Java；
- Python + uv。

因此仓库采用“一个 Git 仓库，多语言独立实验目录”，不强求根目录 `mvn test` 编译全部内容。

Java 子目录自己拥有 `pom.xml`。

## 3. Baseline 导入规则

只有 Prompt 00 使用旧项目路径。

优先级：

1. `LOCAL_PATHS.md` 中 `HANDWRITTEN_AGENT_REPO`；
2. 默认 `../agent-learning`；
3. 找不到则停止导入并请用户提供路径。

不要扫描整个磁盘，不要猜路径。

导入目标：

```text
references/handwritten-agent-v1/stateful-agent
references/handwritten-agent-v1/long-running-agent
```

导入后后续 Prompt 绝不再次依赖外部仓库。

## 4. 各框架代码不要互相依赖

例如：

```text
spring-ai/stateful-agent
```

不得 import：

```text
langchain4j/stateful-agent
```

这样才能进行独立比较。

## 5. 允许重复

Benchmark 的 domain model / SQL schema / Tool 语义可以有一定重复。

为了比较框架，重复比抽一个跨框架 `common-agent-core` 更清晰。

禁止一开始创建：

```text
framework-common
agent-shared-runtime
universal-ai-abstraction
```

否则会把框架差异自己抹平。
