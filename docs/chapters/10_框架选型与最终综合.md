# Chapter 10 — 框架选型与最终综合

## 1. 最终目标不是选“最强框架”

Agent 技术选型不是排行榜。

先问项目需要什么：

```text
模型调用？
Tool？
RAG？
Memory？
复杂 State？
Checkpoint？
HITL？
Multi-Agent？
Sandbox / Shell？
```

再选择最小足够抽象。

## 2. 五层选型思维

### Level 1 — Model SDK

适合：

```text
一次调用
简单 structured output
少量手工 Tool
```

### Level 2 — Application Framework

适合：

```text
业务应用内 AI
Tool + Memory + RAG
Spring/Java 集成
```

代表学习对象：Spring AI、LangChain4j。

### Level 3 — Orchestration Runtime

适合：

```text
复杂流程
长任务
Checkpoint
Pause/Resume
HITL
```

代表学习对象：LangGraph。

### Level 4 — Agent SDK

适合：

```text
Agent/Runner
Handoff
Guardrail
Trace
Multi-Agent primitives
```

### Level 5 — Harness / Managed Runtime

适合：

```text
Coding Agent
Research Agent
Filesystem/Shell
Sandbox
Persistent session
更完整运行环境
```

## 3. 选型案例

### 案例 A

已有大型 Spring Boot 系统，要加内部知识库助手和几个业务查询 Tool。

倾向：从 Spring AI 开始。

原因：应用集成、RAG、Tool、Observability 与 Spring 生态匹配。

### 案例 B

纯 Java CLI/桌面服务，希望弱 Spring，快速用声明式 interface + tools + memory。

倾向：LangChain4j 值得优先评估。

### 案例 C

研究任务可能执行 30 分钟，中间要审批，进程重启后继续。

倾向：需要 durable orchestration；LangGraph 是典型学习对象。

### 案例 D

Gemini / Google Cloud 环境，需要多个 Agent 按 Sequential / Parallel / Loop 组合。

倾向：Google ADK 值得优先评估。

### 案例 E

需要轻量 Agent delegation/handoff，围绕特定模型 SDK 生态快速构建。

倾向：对应厂商 Agent SDK。

### 案例 F

要做类似 Coding Agent：读写文件、跑 Shell、Git、测试、权限审批。

倾向：考虑更厚的 Agent Harness / sandbox runtime，而不是只靠普通 Chat framework。

## 4. 最终综合任务

让 AI 编程工具扫描本仓库所有实现和 Mapping，生成：

```text
docs/comparisons/final_framework_report.md
```

至少包含：

1. 框架分层图；
2. 5 个实现项目的 Mapping 摘要；
3. Java Framework 对比；
4. Runtime vs Framework；
5. SDK vs Harness；
6. 10 个具体场景的选型；
7. 你的个人默认技术栈；
8. “何时不用 Agent Framework”。

## 5. 最后一个重要问题

什么时候应该不用框架？

答案通常包括：

- 需求极小，直接 SDK 更清楚；
- 需要极强自定义 loop；
- 框架抽象与你业务冲突；
- 框架升级风险大于收益；
- 团队更需要透明和可控，而不是抽象层。

## 6. 毕业标准

如果面对一个新框架，你已经能快速问：

```text
它管理 Model 吗？
它管理 Tool Loop 吗？
State 在哪？
Memory 在哪？
Context 怎么注入？
Checkpoint 有吗？
HITL 怎么做？
Trace 在哪？
Multi-Agent 是 deterministic workflow 还是 model-driven delegation？
它到底是 Framework、Runtime、SDK 还是 Harness？
```

那么这一阶段就完成了。
